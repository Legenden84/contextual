# ScreenSettings

Settings, user scope: the Azure AI Foundry connection, exclusion rules and the output-format system prompt.

- Fixed header: Back arrow to the left of the title and a Save checkmark on the right, both icon-only with tooltips. Save keeps its existing save-and-return behavior and saves edits across all groups.
- Persistent left navigation: Azure AI Foundry (initial selection), Models, Exclusions, Output format and Appearance. Only the selected group appears in the right-hand form, which scrolls independently. Switching groups preserves unsaved values and does not save anything.
- Navigation and form share one centered, width-limited layout beneath the header. Extra window width becomes outer margins, keeping navigation beside the form rather than pinned to the window edge.
- Navigation uses the sidebar surface and a hairline divider, with compact control-height text rows. The selected row uses the neutral editor surface, strong ink and an inset 2px accent line on the left, echoing the app's active-tab indicator without a coloured selection fill or chevron. Inactive rows have a subtle hover fill; keyboard focus has a separate visible outline. Tab focuses each entry, Enter or Space selects it, Up/Down selects the previous/next group, and Home/End selects the first/last group.
- Save errors and import feedback stay visible below the header regardless of the selected group. On narrow windows, the form scrolls horizontally without scrolling the navigation away.
- Env import: a starting file/folder field and one “Import .env file…” button open the picker. Importing fills the connection fields for review; saving remains explicit.
- Foundry: endpoint, masked API key, API version, Test connection, and a deployments table with context limit and price per 1M input/output tokens (these drive the context bar and cost estimate).
- Models (its own group, after Azure AI Foundry): the models to route between. A short explanation, then a bordered list with one control-height row per model: its name in strong ink ("New model" in muted ink until it has one), its deployment in muted small type, a "Routing model" tag on the routing model, and "Tier N" on the right ("No tier" in warning ink until one is typed). Rows sort by tier from lowest to highest, with missing or invalid tiers last; equal tiers retain their original order. Selecting a row shows that model's form under "Selected model"; only one model's form is on the page. The selected row uses the selection surface, the others a hover fill; rows take keyboard focus, and Enter or Space selects.
- No model is offered before the user defines one: with an empty list the page says "No models defined. Import an env file that names them, or add one by hand." Below the list, Add model appends an empty model and selects it, and Import .env file… opens the same picker as on the Azure AI Foundry page. The first model added becomes the routing model. Models are stored in settings.json on Save and are there in the next session.
- The form: Name, Deployment, Model name, Tier, Good for, Context limit, Max output tokens, Input, Cached input and Output price per 1M, Tokens per minute. Nothing about a model is built into the app: Tier is required, and each other hint says what an empty field means (the deployment name, 128000 tokens, 16384 tokens, no cost shown, cached input charged like other input, no pacing). A muted line under Model name appears only when the user has described that model under "models" in settings.json. Its last row has Make routing model (or, on the routing model, a sentence saying that it chooses) and a Remove model link. Removing the routing model leaves none, which is said in warning ink above the list; no other model is promoted silently.
- With any model in the list, the single deployment under Azure AI Foundry is not used, and that page says so. What is missing or invalid after saving is listed in warning ink at the top of Models, by variable name. Importing an env file fills the list by model name.
- Exclusions: editable glob chips with the defaults, max file size, Respect .gitignore, Skip binary files, Include hidden files.
- Output format: the editable system prompt that makes the model return full files under `### FILE:` headers so responses can be parsed into diffs.
- Appearance: Dark, Light and Moss schemes, plus the existing System preference. Selection applies and saves immediately. The title-bar toggle cycles only the three explicit schemes; changing it while Settings is open updates the selected option without discarding form edits or letting Save restore an older scheme.
- Reduce motion: an explicit app preference under Appearance, saved with the form. Activity marks become static while their labels continue to report work. Tab focuses the control; Enter or Space toggles it. This preference does not automatically detect the OS motion setting.
